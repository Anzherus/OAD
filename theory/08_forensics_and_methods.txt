КРИМИНАЛИСТИКА КРИПТОВАЛЮТ: МЕТОДОЛОГИЯ И ПРАКТИКА
================================================================

МЕСТО БЛОКЧЕЙН-АНАЛИЗА В КРИМИНАЛИСТИКЕ
================================================================

Компьютерно-техническая экспертиза (КТЭ) криптовалютных дел
включает несколько уровней исследования:

Уровень 1 -- Физический носитель:
  Изъятие и исследование устройств (ПК, телефоны, USB-носители).
  Поиск файлов кошельков, seed-фраз, приватных ключей.
  Инструменты: EnCase, FTK, Autopsy.

Уровень 2 -- Программное обеспечение:
  Анализ установленных кошельков (Electrum, MetaMask, Exodus).
  История транзакций в локальных базах данных.
  Логи приложений, cookies браузера.

Уровень 3 -- Сетевой анализ:
  Анализ трафика (если был перехват).
  IP-адреса при подключении к нодам.
  Использование VPN/Tor (косвенные признаки).

Уровень 4 -- Блокчейн-анализ (данный проект):
  Анализ публичных транзакционных данных.
  Статистические методы для выявления паттернов.
  Построение графа связей между адресами.

СТАТИСТИЧЕСКИЕ МЕТОДЫ В КОНТЕКСТЕ ДЕЛА
================================================================

1. ПРОФИЛИРОВАНИЕ АДРЕСА

Цель: установить характер использования кошелька.

Метрики:
  - Общий объём входящих/исходящих (sumIn, sumOut)
  - Период активности (первая и последняя транзакция)
  - Медианная сумма транзакции (типичный размер операции)
  - Количество уникальных контрагентов

Интерпретация:
  sumIn >> sumOut: накопительный кошелёк (cold storage)
  sumOut >> sumIn: распределительный (payment processor)
  Много мелких входящих + редкие крупные исходящие: биржа
  Равные суммы входящих и исходящих: mixing-сервис

2. ВЫЯВЛЕНИЕ СТРУКТУРИРОВАНИЯ (SMURFING)

Структурирование -- дробление крупной суммы на множество
мелких транзакций для обхода порогов финансового мониторинга.

Признаки в данных:
  - Всплески активности (highBurstiness = true)
  - Много транзакций с похожими суммами
  - Короткие интервалы между транзакциями
  - Высокая доля транзакций чуть ниже круглых сумм

Статистические индикаторы:
  - medianIntervalSec < 300 (5 минут)
  - burstWindows.length > 0
  - Низкое стандартное отклонение сумм (однородные суммы)

3. ВЫЯВЛЕНИЕ DUST ATTACK

Dust attack -- отправка мизерных сумм (пыли) на множество
адресов для их деанонимизации через анализ UTXO.

Признаки:
  - dustShare > 0.35 (более 35% транзакций -- пыль)
  - Много входящих транзакций от разных адресов
  - Суммы значительно ниже комиссии за транзакцию

Флаг: dustHeavy = true

4. ВЫЯВЛЕНИЕ АНОМАЛЬНЫХ ТРАНЗАКЦИЙ

Крупный выброс может означать:
  - Единовременный вывод накопленных средств
  - Получение оплаты за крупную сделку
  - Ошибочную транзакцию
  - Консолидацию адресов

Метод: правило Тьюки (Q3 + 3*IQR)
Флаг: largeOutlier = true

5. ПРОВЕРКА ЗАКОНА БЕНФОРДА

Применяется как дополнительный инструмент скрининга.

Сценарии отклонения:
  - Синтетические транзакции (автоматически сгенерированные)
  - Округлённые суммы (100, 200, 500 единиц)
  - Структурирование (суммы в узком диапазоне)
  - Манипуляция данными

Важно: отклонение требует объяснения, но не является
само по себе доказательством нарушения.

ЭВРИСТИЧЕСКИЕ ФЛАГИ: ИНТЕРПРЕТАЦИЯ
================================================================

Флаг highBurstiness:
  Условие: найдено >= 1 burst-окно
  Возможные объяснения:
    [криминальные] mixing, structuring, automated fraud
    [легитимные]   биржевой арбитраж, автоматический трейдинг,
                   технические операции (rebalancing)

Флаг dustHeavy:
  Условие: доля пыли > 35%
  Возможные объяснения:
    [криминальные] dust attack, деанонимизация жертв
    [легитимные]   тестовые транзакции, старые UTXO,
                   получение airdrop-токенов

Флаг largeOutlier:
  Условие: max > Q3 + 3*IQR при n >= 5
  Возможные объяснения:
    [криминальные] вывод похищенных средств, крупная сделка
    [легитимные]   продажа актива, получение зарплаты,
                   консолидация кошельков

ПРИНЦИП: каждый флаг -- это вопрос, а не ответ.

ОГРАНИЧЕНИЯ СТАТИСТИЧЕСКОГО АНАЛИЗА
================================================================

1. Корреляция ≠ причинность
   Наличие всплеска активности не доказывает умысел.
   Необходим контекст и дополнительные доказательства.

2. Выборочность данных
   Анализируются только последние N транзакций.
   Полная история может содержать другие паттерны.

3. Псевдоанонимность
   Адрес != личность. Для установления владельца нужны:
   - KYC данные биржи (через судебный запрос)
   - Данные с устройства подозреваемого
   - Показания свидетелей

4. Технические ограничения API
   - Etherscan не возвращает internal transactions по умолчанию
   - ERC-20 переводы требуют отдельного запроса (action=tokentx)
   - Данные могут быть неполными при высокой нагрузке

5. Изменчивость блокчейна
   - Реорганизации цепи (редко, но возможно)
   - Pending транзакции (ещё не в блоке)

РЕКОМЕНДАЦИИ ПО ПРИМЕНЕНИЮ В ЭКСПЕРТИЗЕ
================================================================

1. Документирование источников:
   Зафиксировать URL API, дату и время запроса, версию API,
   количество полученных записей.

2. Верификация данных:
   Проверить несколько транзакций через независимый
   блокчейн-эксплорер (blockchain.com, etherscan.io).

3. Экспорт данных:
   Использовать функцию "Экспорт JSON" для сохранения
   полного отчёта с метаданными (generatedAtIso, options).

4. Формулировка выводов:
   Использовать вероятностные формулировки:
   "данные свидетельствуют о...", "не исключается...",
   "характерно для...", а не категоричные утверждения.

5. Альтернативные гипотезы:
   Для каждого выявленного паттерна рассмотреть
   легитимное объяснение.

6. Комплексность:
   Статистический анализ блокчейна -- один из методов.
   Выводы должны подкрепляться другими доказательствами.
