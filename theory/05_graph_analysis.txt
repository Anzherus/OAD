ТЕОРИЯ ГРАФОВ В БЛОКЧЕЙН-АНАЛИТИКЕ
================================================================

Транзакционная сеть блокчейна естественно представляется как
направленный взвешенный граф G = (V, E, w), где:

  V -- множество вершин (адреса кошельков)
  E -- множество рёбер (направления потоков средств)
  w: E -> R+ -- весовая функция (суммарный объём переводов)

Граф направленный: ребро (A -> B) означает, что A отправлял
средства на B. Обратное не обязательно верно.

Граф взвешенный: вес ребра = суммарный объём всех переводов
между двумя адресами в данном направлении.

ПОСТРОЕНИЕ ГРАФА В ПРИЛОЖЕНИИ
================================================================

Приложение строит эго-граф (ego graph) -- подграф, центром
которого является фокусный адрес.

Алгоритм buildTransactionGraph:

1. Нормализация адресов в lowercase для консистентности

2. Агрегация рёбер:
   Для каждой транзакции:
   - Если amountNative >= 0 (входящая):
     ребро: from_address --> focus
     вес += |amountNative|
   - Если amountNative < 0 (исходящая):
     ребро: focus --> to_address
     вес += |amountNative|
   - Самопетли (from == focus или to == focus) пропускаются

3. Сортировка рёбер:
   Первичный ключ: вес (по убыванию)
   Вторичный ключ: количество транзакций (по убыванию)
   Это гарантирует, что нулевые рёбра (контрактные вызовы)
   попадают в граф, но после рёбер с реальными суммами.

4. Обрезка до maxEdges (по умолчанию 40)
   Берутся только топ-N рёбер по весу.

5. Обрезка узлов до maxNodes (по умолчанию 24)
   Если узлов больше лимита -- оставляем узлы с наибольшим
   суммарным весом смежных рёбер (degree-weighted pruning).
   Фокусный адрес всегда сохраняется.

КЛЮЧ РЕБРА
================================================================

Рёбра агрегируются по ключу: "source\0target"
(разделитель -- нулевой байт, не встречается в адресах)

Это позволяет суммировать несколько транзакций между одной
парой адресов в одно ребро с суммарным весом.

Пример:
  Tx1: A -> Focus, 0.5 ETH
  Tx2: A -> Focus, 1.2 ETH
  Tx3: A -> Focus, 0.0 ETH (контрактный вызов)
  --> Одно ребро A -> Focus, вес = 1.7, txIds = [tx1, tx2, tx3]

СТРУКТУРА ДАННЫХ
================================================================

TransactionGraph:
  nodes: Array<{
    id: string       -- адрес (lowercase)
    label: string    -- отображаемое имя (с пометкой "(фокус)")
    isFocus: boolean -- является ли фокусным адресом
  }>
  edges: Array<{
    source: string   -- адрес отправителя
    target: string   -- адрес получателя
    weight: number   -- суммарный объём (в нативных единицах)
    txIds: string[]  -- список хешей транзакций
  }>

ВИЗУАЛИЗАЦИЯ (FlowPanel.tsx)
================================================================

Используется библиотека @xyflow/react (React Flow).

Расположение узлов (layout):
  - Фокусный адрес: центр (0, 0)
  - Остальные узлы: равномерно по окружности радиуса R=260px
  - Угол i-го узла: angle = 2π * i / n

Стилизация:
  - Фокусный узел: фиолетовая рамка, полупрозрачный фон
  - Остальные узлы: серая рамка, тёмный фон
  - Рёбра: фиолетовые стрелки, подпись = вес (6 знаков)

Интерактивность:
  - Перетаскивание узлов
  - Масштабирование колесом мыши
  - Миникарта для навигации
  - Кнопка полноэкранного режима (Escape для выхода)
  - Бейдж с количеством узлов и рёбер

МЕТОДЫ АНАЛИЗА ГРАФА В КРИМИНАЛИСТИКЕ
================================================================

1. Анализ степени вершины (degree analysis)
   in-degree: количество уникальных отправителей
   out-degree: количество уникальных получателей
   Высокий in-degree при низком out-degree -- накопительный адрес.
   Высокий out-degree -- распределительный адрес (mixer output).

2. Анализ хопов (hop analysis)
   Расширение графа на 1-2 хопа от фокуса позволяет выявить
   связанные адреса, которые могут принадлежать тому же лицу.
   В приложении реализован только 1 хоп (прямые контрагенты).

3. Кластеризация адресов
   Адреса, часто взаимодействующие между собой, могут
   принадлежать одному субъекту (exchange, mixer, wallet cluster).
   В приложении не реализована (требует полного графа сети).

4. Анализ потоков (flow analysis)
   Отслеживание движения конкретной суммы через цепочку адресов.
   Позволяет установить конечного получателя средств.

5. Выявление паттернов
   - "Звезда" (star): один центральный адрес, много листьев
     --> характерно для exchange hot wallet
   - "Цепочка" (chain): A -> B -> C -> D
     --> характерно для попытки запутать след
   - "Веер" (fan-out): один адрес -> много адресов
     --> характерно для вывода средств / dust attack

ОГРАНИЧЕНИЯ РЕАЛИЗАЦИИ
================================================================

1. Только прямые контрагенты (1 хоп)
   Полный анализ требует рекурсивного обхода графа.

2. Только нативная валюта
   Не учитываются ERC-20 токены, NFT, internal transactions ETH.

3. Упрощённый layout
   Реальные инструменты (Chainalysis, Elliptic) используют
   force-directed layout с учётом весов рёбер.

4. Нет идентификации адресов
   Реальные инструменты сопоставляют адреса с известными
   сущностями (биржи, миксеры, darknet markets).
