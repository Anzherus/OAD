ПАТТЕРНЫ ПРОЕКТИРОВАНИЯ
================================================================

1. Domain-Driven Design (упрощённый)
   Бизнес-логика изолирована в src/domain/ и не зависит от UI.
   UI-компоненты только отображают данные, не вычисляют их.

2. Pure Functions
   Все функции в domain/ -- чистые (pure functions):
   - Нет побочных эффектов
   - Одинаковый вход всегда даёт одинаковый выход
   - Легко тестировать

3. Adapter Pattern
   src/adapters/ изолирует работу с внешними API.
   Если API изменится -- меняется только адаптер, не логика.

4. Composition
   buildFullReport() собирает полный отчёт из результатов
   отдельных функций: describeTransfers + temporalFromTransfers
   + benfordFirstDigit + computeFlags + buildTransactionGraph.

ПРОКСИ VITE ДЛЯ CORS
================================================================

Etherscan API не поддерживает CORS для браузерных запросов.
Решение: Vite dev proxy перенаправляет запросы через сервер.

vite.config.ts:
  proxy: {
    '/etherscan-api': {
      target: 'https://api.etherscan.io',
      changeOrigin: true,
      rewrite: (p) => p.replace(/^\/etherscan-api/, '')
    }
  }

Запрос браузера: /etherscan-api/v2/api?chainid=1&...
Реальный запрос: https://api.etherscan.io/v2/api?chainid=1&...

В production (Netlify): netlify.toml содержит аналогичный redirect.

НОРМАЛИЗАЦИЯ АДРЕСОВ
================================================================

Проблема: Ethereum адреса могут быть в разном регистре:
  0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045  (EIP-55 checksum)
  0xd8da6bf26964af9d7eed9e03e53415d37aa96045  (lowercase)

Оба варианта обозначают один и тот же адрес.

Решение в коде:
  - Адаптер etherscan.ts: все адреса сохраняются в lowercase
    (переменные from и to уже lowercase, они и сохраняются)
  - buildGraph.ts: focusAddress.trim().toLowerCase()
  - buildGraph.ts: r.from?.toLowerCase(), r.to?.toLowerCase()

Это гарантирует корректное сравнение адресов независимо от
регистра, в котором они пришли из API или введены пользователем.

ВЫЧИСЛЕНИЕ СУММ ETH
================================================================

Проблема: JavaScript number не может точно представить большие
целые числа (wei). 1 ETH = 10^18 wei, что превышает Number.MAX_SAFE_INTEGER.

Решение: использование BigInt для промежуточных вычислений:
  const wei = BigInt(t.value || '0')
  const eth = Number(wei) / 1e18

BigInt точно хранит целые числа любого размера.
Деление на 1e18 переводит в ETH с достаточной точностью для
статистического анализа (потеря точности в 15-16 знаке).

ИМПОРТ ФАЙЛОВ (csvJson.ts)
================================================================

JSON формат (два варианта):
  1. Массив: [{timestamp, amount, from, to, event_type}, ...]
  2. Объект: {transfers: [{...}, ...]}

CSV формат:
  - Первая строка может быть заголовком (timestamp,amount,...)
  - Разделитель: запятая
  - Поля: timestamp, amount, from, to, event_type
  - Timestamp: Unix-секунды, Unix-миллисекунды или ISO 8601 строка

Парсинг timestamp:
  - Число > 1e12: считается миллисекундами, делится на 1000
  - Число <= 1e12: считается секундами
  - Строка: Date.parse() -> миллисекунды -> секунды
