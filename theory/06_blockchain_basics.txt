================================================================
ОСНОВЫ БЛОКЧЕЙНА И ЦИФРОВЫЕ СЛЕДЫ
================================================================

ЧТО ТАКОЕ БЛОКЧЕЙН
================================================================

Блокчейн -- распределённый реестр транзакций, организованный
в виде цепочки блоков. Каждый блок содержит:
  - Хеш предыдущего блока (связь в цепочку)
  - Временную метку (timestamp)
  - Набор транзакций
  - Nonce (для Proof-of-Work)
  - Хеш текущего блока (SHA-256 для BTC, Keccak-256 для ETH)

Ключевые свойства для криминалистики:
  1. Неизменяемость: записанная транзакция не может быть удалена
  2. Публичность: все транзакции видны любому наблюдателю
  3. Псевдоанонимность: адреса не привязаны к личности напрямую
  4. Верифицируемость: любой может проверить любую транзакцию

BITCOIN: МОДЕЛЬ UTXO
================================================================

Bitcoin использует модель UTXO (Unspent Transaction Output).

Транзакция Bitcoin состоит из:
  vin (inputs):  ссылки на предыдущие UTXO (откуда берутся BTC)
  vout (outputs): новые UTXO (куда идут BTC)

Пример:
  Input:  UTXO на 1.5 BTC (адрес A)
  Output1: 0.8 BTC -> адрес B (получатель)
  Output2: 0.69 BTC -> адрес A (сдача)
  Fee: 0.01 BTC (майнеру)

Нормализация в приложении (mempool.ts):
  1. Суммируем все inputs от фокусного адреса (satIn)
  2. Суммируем все outputs на фокусный адрес (satOut)
  3. delta = satOut - satIn
  4. amountNative = delta / 1e8 (перевод из сатоши в BTC)

Если delta > 0: адрес получил BTC (входящая транзакция)
Если delta < 0: адрес отправил BTC (исходящая транзакция)

Единицы: 1 BTC = 100,000,000 сатоши (satoshi)

ETHEREUM: МОДЕЛЬ ACCOUNT
================================================================

Ethereum использует модель аккаунтов (Account-based model).

Два типа аккаунтов:
  EOA (Externally Owned Account): обычный кошелёк, управляется
    приватным ключом. Адрес: 0x + 40 hex символов.
  Contract Account: смарт-контракт, управляется кодом.

Транзакция Ethereum содержит:
  from:      адрес отправителя
  to:        адрес получателя (EOA или контракт)
  value:     количество ETH в wei (1 ETH = 10^18 wei)
  data:      данные вызова (для контрактов)
  gasLimit:  максимум газа
  gasPrice:  цена газа в gwei
  nonce:     порядковый номер транзакции от отправителя

Нормализация в приложении (etherscan.ts):
  1. value в wei -> ETH: eth = Number(BigInt(value)) / 1e18
  2. Если to == focus: amountNative = +eth (входящая)
  3. Если from == focus: amountNative = -eth (исходящая)
  4. Включаются транзакции с value=0 (контрактные вызовы)

Единицы: 1 ETH = 10^18 wei = 10^9 gwei

АДРЕСА КРИПТОВАЛЮТ
================================================================

Bitcoin адреса (форматы):
  Legacy (P2PKH):  начинается с 1, длина 25-34 символа
                   Пример: 1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa
  P2SH:            начинается с 3, длина 25-34 символа
  Bech32 (P2WPKH): начинается с bc1, длина 42 символа
                   Пример: bc1qxy2kgdygjrsqtzq2n0yrf2493p83kkfjhx0wlh
  Testnet:         начинается с tb1 или m/n

Ethereum адреса:
  Формат: 0x + 40 hex символов (20 байт)
  Пример: 0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045
  EIP-55: checksum через смешанный регистр (не влияет на функцию)
  В приложении все адреса нормализуются в lowercase.

ЦИФРОВЫЕ СЛЕДЫ В БЛОКЧЕЙНЕ
================================================================

Цифровые следы (digital traces) -- это данные, оставляемые
субъектом в процессе использования криптовалюты:

1. Транзакционные следы:
   - Хеши транзакций (txid/hash) -- уникальные идентификаторы
   - Адреса отправителей и получателей
   - Суммы и временные метки
   - Комиссии (gas fee для ETH)

2. Сетевые следы:
   - IP-адрес при трансляции транзакции в сеть
   - Временная метка получения узлом (mempool timestamp)
   - Паттерны подключения к нодам

3. Метаданные блоков:
   - Номер блока (block height)
   - Хеш блока
   - Адрес майнера/валидатора

4. Следы на устройствах:
   - Файлы кошелька (wallet.dat для Bitcoin Core)
   - Приватные ключи и seed-фразы
   - История браузера (web-кошельки)
   - Логи приложений

ПСЕВДОАНОНИМНОСТЬ VS АНОНИМНОСТЬ
================================================================

Блокчейн псевдоанонимен, а не анонимен:
  - Адреса не содержат имён, но все транзакции публичны
  - Деанонимизация возможна через:
    * KYC данные бирж (при выводе на фиат)
    * Анализ кластеров адресов
    * Корреляцию с IP-адресами
    * Анализ паттернов поведения
    * Dust attacks (отправка мелких сумм для отслеживания)

Методы повышения анонимности (и их следы):
  - Mixing/Tumbling: характерные временные паттерны, равные суммы
  - CoinJoin: транзакции с множеством входов и выходов
  - Privacy coins (Monero, Zcash): скрытые суммы и адреса
  - Lightning Network: off-chain транзакции

ПРОЦЕССУАЛЬНЫЕ АСПЕКТЫ
================================================================

При использовании блокчейн-анализа в уголовном деле:

1. Цепочка хранения данных (Chain of Custody):
   - Фиксация источника данных (API endpoint, дата запроса)
   - Хеш-суммы полученных данных для верификации
   - Документирование инструментов анализа

2. Верификация данных:
   - Данные из публичного API должны быть верифицированы
     через независимый узел блокчейна
   - Скриншоты недостаточны -- нужны сырые данные

3. Экспертное заключение:
   - Статистические методы должны быть описаны и обоснованы
   - Выводы должны быть сформулированы с указанием
     степени достоверности
   - Альтернативные объяснения должны быть рассмотрены

4. Ограничения:
   - Публичные API могут иметь задержки или неполные данные
   - Адрес != личность (нужны дополнительные доказательства)
   - Технические артефакты могут имитировать подозрительные паттерны
