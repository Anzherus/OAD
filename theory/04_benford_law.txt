ЗАКОН БЕНФОРДА (BENFORD'S LAW)
================================================================

Файл: src/domain/stats/benford.ts

ИСТОРИЯ И СУТЬ ЗАКОНА
================================================================

Закон Бенфорда (закон первой цифры) -- эмпирическое наблюдение,
впервые описанное Саймоном Ньюкомом в 1881 году и переоткрытое
Фрэнком Бенфордом в 1938 году.

Закон утверждает: в наборах "естественных" числовых данных
(финансовые отчёты, размеры городов, физические константы,
длины рек) первая значащая цифра d распределена неравномерно.

Цифра 1 встречается чаще всего (~30%), цифра 9 -- реже всего (~5%).

МАТЕМАТИЧЕСКАЯ ФОРМУЛИРОВКА
================================================================

Вероятность того, что первая значащая цифра равна d:

  P(d) = log_10(1 + 1/d),   d ∈ {1, 2, 3, 4, 5, 6, 7, 8, 9}

Таблица ожидаемых частот:
  d=1: log_10(2/1)   = 0.30103  ≈ 30.1%
  d=2: log_10(3/2)   = 0.17609  ≈ 17.6%
  d=3: log_10(4/3)   = 0.12494  ≈ 12.5%
  d=4: log_10(5/4)   = 0.09691  ≈  9.7%
  d=5: log_10(6/5)   = 0.07918  ≈  7.9%
  d=6: log_10(7/6)   = 0.06695  ≈  6.7%
  d=7: log_10(8/7)   = 0.05799  ≈  5.8%
  d=8: log_10(9/8)   = 0.05115  ≈  5.1%
  d=9: log_10(10/9)  = 0.04576  ≈  4.6%

В коде эти значения хранятся как константа:
  const BENFORD = [0.301, 0.176, 0.125, 0.097, 0.079, 0.067, 0.058, 0.051, 0.046]

ПОЧЕМУ ЗАКОН РАБОТАЕТ
================================================================

Закон Бенфорда выполняется для данных, охватывающих несколько
порядков величин (например, от 0.001 до 1000).

Интуиция: если число равномерно распределено в логарифмической
шкале, то вероятность первой цифры d пропорциональна длине
интервала [log(d), log(d+1)] = log(1 + 1/d).

Условия применимости:
  + Данные охватывают несколько порядков величин
  + Нет искусственных ограничений (минимум/максимум)
  + Достаточный объём выборки (рекомендуется >= 100, минимум 30)
  - НЕ работает для данных с узким диапазоном (например, цены
    в диапазоне 100-200 рублей)
  - НЕ работает для равномерно распределённых данных
  - НЕ работает для округлённых сумм (100, 200, 500...)

ПРИМЕНЕНИЕ В ФИНАНСОВОЙ КРИМИНАЛИСТИКЕ
================================================================

Марк Нигрини (Mark Nigrini) в 1990-х годах разработал методику
применения закона Бенфорда для выявления финансовых мошенничеств.

Логика: если человек фальсифицирует финансовые данные, он
интуитивно распределяет цифры равномерно (каждая цифра ~11%),
что резко отличается от закона Бенфорда.

Применение к криптовалютам:
  - Суммы транзакций реального кошелька должны примерно следовать
    закону Бенфорда (если диапазон достаточно широк)
  - Синтетические транзакции (автоматически сгенерированные
    одинаковые суммы) дадут отклонение
  - Структурирование (дробление на суммы чуть ниже порога)
    даст аномальный пик на определённой цифре

МЕРА ОТКЛОНЕНИЯ: MAD (Mean Absolute Deviation)
================================================================

Метрика Нигрини для оценки соответствия закону Бенфорда:

  MAD = (1/9) * Σ_{d=1}^{9} |obs(d) - P(d)|

где:
  obs(d) = (количество транзакций с первой цифрой d) / n
  P(d)   = ожидаемая вероятность по закону Бенфорда
  n      = общее количество транзакций

Шкала интерпретации MAD (по Нигрини):
  MAD < 0.006  -- точное соответствие (идеальные данные)
  MAD < 0.012  -- приемлемое соответствие
  MAD < 0.015  -- приблизительное соответствие (в коде: 'rough_match')
  MAD < 0.05   -- слабое соответствие (в коде: 'weak')
  MAD >= 0.05  -- значительное отклонение (требует внимания)

В коде используется упрощённая шкала:
  if (mad < 0.015) conformity = 'rough_match'
  else             conformity = 'weak'
  if (rows < 30)   conformity = 'insufficient_data'

АЛГОРИТМ ИЗВЛЕЧЕНИЯ ПЕРВОЙ ЦИФРЫ
================================================================

Функция leadingDigit(x):
1. Берём |x| (абсолютное значение)
2. Пока число >= 10: делим на 10
3. Пока число < 1 и > 0: умножаем на 10
4. Берём floor() -- это и есть первая значащая цифра

Примеры:
  leadingDigit(3.14)   = 3
  leadingDigit(0.0025) = 2  (0.0025 -> 0.025 -> 0.25 -> 2.5 -> floor=2)
  leadingDigit(150)    = 1  (150 -> 15 -> 1.5 -> floor=1)
  leadingDigit(0)      = null (ноль исключается)

КОД (benford.ts)
================================================================

function leadingDigit(x: number): number | null {
  if (!Number.isFinite(x) || x === 0) return null
  let a = Math.abs(x)
  while (a >= 10) a /= 10
  while (a < 1 && a > 0) a *= 10
  return Math.floor(a)  // гарантированно 1..9
}

export function benfordFirstDigit(rows): BenfordResult | null {
  const vals = rows.map(r => Math.abs(r.amountNative)).filter(v => v > 0)
  if (vals.length < 30) return { conformity: 'insufficient_data', ... }

  // Подсчёт первых цифр
  const counts = {1:0, 2:0, ..., 9:0}
  for (const v of vals) {
    const d = leadingDigit(v)
    if (d) counts[d]++
  }

  // Вычисление MAD
  const n = vals.length
  let mad = 0
  for (let d = 1; d <= 9; d++) {
    const obs = counts[d] / n
    mad += Math.abs(obs - BENFORD[d-1])
  }
  mad /= 9

  return { digitDistribution: counts, expectedBenford: ..., mad, conformity }
}

ВАЖНЫЕ ОГОВОРКИ
================================================================

1. Отклонение от закона Бенфорда НЕ является доказательством
   мошенничества или преступления.

2. Закон Бенфорда -- это инструмент скрининга, указывающий на
   необходимость дополнительной проверки.

3. Для криптовалют закон работает хуже, чем для бухгалтерских
   данных, из-за специфики ценообразования и округления.

4. Малые выборки (< 100 транзакций) дают ненадёжные результаты.

5. В реальной экспертизе результат Бенфорда должен подкрепляться
   другими методами анализа.
